Le coût fixe (3 Go) n'est dans aucune ligne réécrivable ; la vérification est une longue traîne (≈ 1 000 fichiers de requêtes Prisma à 2-10 k types chacun ; aucun motif d'énorme union, d'`as const` géant ou d'`include` profond dominant). Les vrais points chauds ont été corrigés à la source — le JSON du contrat des actions typé par `contrat.genere.d.json.ts` (870 ko de littéraux inférés pour rien : 17 600 types, 2 s ; `allowArbitraryExtensions`), une union de deux `PrismaPromise` annotée dans `engagement.ts` (220 000 instanciations), le constructeur du routeur Mastra (union de 8 900 identifiants de modèles) vu par sa seule forme utile dans `traces.ts` — mais ensemble ils pèsent ≈ 6 % : **aucun lot d'annotations ne rend 1,3 Go.** Le levier est donc de ne jamais tenir les types de toute l'application à la fois : `scripts/typecheck-production.mjs` coupe les fichiers de production (triés, contigus) en tranches de ≤ 650, chacune dans SON processus à tas de 4 300 Mo, programme = ses fichiers + toutes les déclarations globales (`.d.ts`, `declare global|module`) + la fermeture de leurs imports. Le type d'un fichier ne dépend que de ce qu'il importe : chaque fichier est vérifié comme par tsc d'un seul tenant — **prouvé** en injectant une erreur dans chacune des 6 tranches (6 lignes identiques chez tsc et ici). Mesuré : pic RSS 3 489 Mo (tas vivant max 3 306) au lieu d'un OOM à 4 300 Mo, ≈ 5 min. Le nombre de tranches suit le nombre de fichiers : le code qui grossit ajoute des tranches, pas de la mémoire par tranche. Une tranche qui ne tient plus ÉCHOUE (et le dit) au lieu de passer au rejeu ; au-delà de 3 700 Mo de tas vivant, le script prévient. Branché partout où le typecheck de production passe : `build:render`, `next.config.mjs` (un `next build` NU sur Render, §118.208), CI (`npm run typecheck:production`) ; `src/lib/infra/typecheck-production.test.ts` (dans `npm test`) échoue si l'un de ces branchements revient au tsc d'un seul tenant ou si le découpage perd un fichier ou une déclaration globale. `npm run typecheck` (tout, tests compris, tas 8 Go) est inchangé : c'est la porte de développement, pas celle du déploiement.
